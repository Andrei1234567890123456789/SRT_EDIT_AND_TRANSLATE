1. The original SRT enters the application

Suppose the file contains:

289

минутки.

00:14:22,320 --> 00:14:23,560

Python reads the file and parses every subtitle into an internal structure:

Subtitle 289
  number: 291
  timestamp: 00:14:24,320 --> 00:14:25,880
  text: Благодаря ви за вниманието!

Importantly, Python keeps the number and timestamp.

2. Python divides the subtitles into chunks

Currently we use:

CHUNK_SIZE = 80
CONTEXT_SIZE = 10

So imagine we have 328 subtitles.

The primary chunks are:

Chunk 1:  1–80
Chunk 2: 81–160
Chunk 3: 161–240
Chunk 4: 241–320
Chunk 5: 321–328

But we also give the AI surrounding context.

For example, chunk 4 might look conceptually like:

Context:
231–240

Primary:
241–320

Context:
321–328

The context isn't independently translated. It is there so the AI understands what's being discussed.

3. Python sends only text + IDs to the AI

This is very deliberate.

The AI does not receive:

241
00:12:00,000 --> 00:12:02,000
...

Instead, it receives something like:

CONTEXT [231]
...

CONTEXT [232]
...

TRANSLATE [241]
...

TRANSLATE [242]
...

TRANSLATE [243]
...

The timestamps never need to be generated by the AI.

That's a major safety feature.

4. The AI translates using the surrounding context

Imagine Bulgarian subtitles:

[100]
Това е нещо, което трябва да

[101]
имате предвид при раждането.

If the AI sees both, it understands:

"Това е нещо, което трябва да имате предвид при раждането."

and can produce:

[100]
Это то, что следует

[101]
учитывать во время родов.

rather than treating each subtitle as an isolated sentence.

This is why we use context.

5. The AI returns only translated text

The expected response is:

[241]
translation...

[242]
translation...

[243]
translation...

It should not return timestamps.

It should not return a complete SRT.

It should not change the IDs.

6. Python checks the AI response

This is where your recent error came from.

Python knows that the chunk required:

[241]
[242]
[243]
...
[291]
...
[320]

If the AI returns:

[241]
[242]
...
[290]
[292]

Python detects:

Missing ID: 291

and rejects the response.

So we don't silently produce a damaged SRT.

7. Retry mechanism

With the retry system we added, the process becomes:

Send chunk
     │
     ▼
AI response
     │
     ▼
Validate IDs
     │
 ┌───┴────┐
 │        │
Valid   Invalid
 │        │
 ▼        ▼
Continue  Retry
          │
          ▼
       AI again

Currently we allow:

MAX_RETRIES = 3

So one malformed response doesn't kill the entire translation.

8. Python stores the translations

Once a chunk passes validation, Python creates a dictionary roughly like:

{
    "241": "translated text...",
    "242": "translated text...",
    "243": "translated text..."
}

It does this for every chunk.

Eventually:

{
    "1": "...",
    "2": "...",
    ...
    "328": "..."
}
9. Python reconstructs the SRT

This is the really important part.

Python goes back to the original SRT and takes:

Original number
Original timestamp
AI translation

For example:

Original:

291
00:14:24,320 --> 00:14:25,880
Благодаря ви за вниманието!

AI provides:

[291]
Спасибо за внимание!

Python combines them:

291
00:14:24,320 --> 00:14:25,880
Спасибо за внимание!

The AI never gets to decide what the timestamp is.

10. Final validation

Before saving, Python compares the original and reconstructed files.

It checks:

Number of entries
Original:     328
Translation:  328
Subtitle numbers
Original:     1, 2, 3 ... 328
Translation:  1, 2, 3 ... 328
Timestamps

For every subtitle:

Original:
00:14:24,320 --> 00:14:25,880

Translated:
00:14:24,320 --> 00:14:25,880

They must be identical.

Translation text

It checks that every subtitle has non-empty translated text.

Only after everything passes does Python save the file.

Why this architecture is good

It separates responsibilities:

Task	Who does it?
Read SRT	Python
Identify subtitles	Python
Preserve numbering	Python
Preserve timestamps	Python
Decide translation	AI
Understand surrounding context	AI
Translate naturally	AI
Ensure every subtitle was translated	Python
Reconstruct SRT	Python
Final validation	Python
Save file	Python

The biggest advantage is that the AI is no longer responsible for things it doesn't need to be responsible for.

One weakness in the current algorithm

There is one thing I would change next: our CHUNK_SIZE = 80 is still somewhat crude.

For a short subtitle-heavy section, 80 subtitles might be very little text. For a lecture with long subtitles, 80 could be a lot.

More importantly, the current algorithm doesn't yet give the AI long-term terminology memory. If the speaker introduces a specialized term early in a 2-hour lecture, we want the same term translated consistently much later.

That's why I'd make the next major improvement adaptive chunks + a translation glossary/terminology memory. That would improve the quality of long lectures substantially without changing the safety mechanism we've built.
